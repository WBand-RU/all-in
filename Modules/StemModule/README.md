# Загрузка папки мультитрека

Папка загружается как отдельная сессия. До завершения всей сессии её стемы
не хранятся как `Stem` и не попадают в список песни или источники миксов.

1. `POST /stem-api/songs/{songId}/stems/batch` принимает `batchId` (UUID клиента)
   и `files`. Сначала сохраняется `StemUploadBatch` со всеми идентификаторами
   и ключами объектов для очистки. Повтор того же запроса безопасен.
2. Перед каждым PUT клиент получает свежую ссылку через
   `POST /stem-api/songs/{songId}/stem-uploads/{batchId}/files/{fileId}/upload-url`.
   После PUT `/files/{fileId}/complete` проверяет размер, MIME и SHA-256.
3. `POST /stem-api/songs/{songId}/stem-uploads/{batchId}/complete` требует готовности
   **всех** файлов. Создание стемов, изменение версии коллекции, закрытие сессии
   и событие `StemsChanged` через outbox сохраняются в одной транзакции Marten.
   Повтор завершения не создаёт дубликаты.
4. При ошибке или отмене клиент вызывает
   `DELETE /stem-api/songs/{songId}/stem-uploads/{batchId}`. Сессия закрывается
   до удаления объектов. Завершённая сессия не удаляется этим маршрутом.

Фоновая очистка раз в минуту повторяет удаление отменённых сессий и закрывает
заброшенные сессии через час. Очищаются также уже проверенные файлы.
Ключи сохраняются в манифесте: удаление повторяется до истечения выданных
ссылок с запасом в десять минут, чтобы убрать поздние PUT после отмены.

Клиент делает до трёх попыток для сетевых ошибок, 408, 429, 5xx и временной
недоступности объекта при проверке. Ошибки прав, контрольной суммы и валидации
не повторяются. Автоматический запуск миксов происходит после завершения
сессии; его ошибка не меняет успешный результат загрузки файлов.
