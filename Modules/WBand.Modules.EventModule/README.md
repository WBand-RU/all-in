# Events

Модуль мероприятий и выступлений группы. Владеет контекстом `EventDataContext`, схемой PostgreSQL `events`, миграциями и упорядоченным списком идентификаторов песен. Песни хранятся в своём модуле; удаление события не удаляет песни.

HTTP через Wolverine: `GET/POST /api/events`, `GET/PUT/DELETE /api/events/{eventId}`. Чтение доступно действующим участникам группы, изменения — владельцу и администраторам. При обновлении обязателен `expectedVersion`; устаревшие и конкурирующие изменения возвращают 409. Событие содержит название, дату/время (UTC), место, описание и до 200 уникальных песен одной группы.

Запросы `CheckEventBandAccess`, `GetEventUserBands`, `ResolveEventSongs` адаптируются хостом через Wolverine к публичным контрактам групп и песен. Модуль не обращается к таблицам или внутренним реализациям других модулей. Недоступные/удалённые песни остаются в сохранённом списке как ссылки; интерфейс сообщает об этом и позволяет их убрать. При удалении группы её события перестают быть доступны через проверку актуального членства.

На фронтенде: `/app/events`, `/app/events/new`, `/app/events/{id}`, `/app/events/{id}/edit`, `/app/events/{id}/stage`. Режим сцены выводит все песни и секции по порядку, позволяет переходить по номерам и изменять размер текста. Превью песни и сцена используют общий безопасный рендерер квадратных скобок: `[Am]`, `[G/B]`, `[| Am | Dm | C | G |]`. HTML остаётся текстом; исходные пробелы и переносы строк сохраняются.
