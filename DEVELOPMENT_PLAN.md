# План развития WBand

## Исходная точка

Цель — модульный монолит на ASP.NET Core (`App/WBand.WebAPI`) с доменными модулями `WBand.Modules.*`. Keycloak отвечает только за аутентификацию и управление учётными записями; прикладной профиль и права внутри бэнда принадлежат WBand. WolverineFX — единый механизм HTTP-обработчиков и событий, Marten/PostgreSQL — основное хранилище, RabbitMQ — транспорт сообщений. Каталоги `Services/` и `src/` не развивать.

## 1. Укрепить основу приложения

1. Описать стандарт модуля: composition root, `Domain`, `Application`, `Contracts`, `Endpoints`, `Infrastructure`, изоляция схемы Marten и тестовый проект `WBand.Modules.<Name>.Tests`.
2. Централизовать подключение Wolverine, Marten, RabbitMQ, OpenAPI, health checks и конфигурацию через options с валидацией при запуске.
3. Убрать ручное чтение RabbitMQ в `UserModule`, заменить его Wolverine-слушателем. Исправить конфигурацию `FileModule` (bucket сейчас читается из `S3_REGION`), добавить авторизацию и валидацию к файловым endpoint'ам.
4. Настроить тестовую инфраструктуру: unit-тесты домена и интеграционные тесты HTTP/Marten/Wolverine с изолированным окружением.

**Готово, когда:** API запускается с проверенной конфигурацией, сообщения обрабатываются через Wolverine, а CI выполняет build, test, lint и frontend build.

## 2. Завершить идентификацию и модуль Band

1. Довести `UserModule`: идемпотентная синхронизация пользователя после входа через Keycloak, `CurrentUser` из JWT, аудит событий входа.
2. Создать `WBand.Modules.BandModule`: бэнды, участники, роли Owner/Admin/Editor/Player/Viewer/Publisher и разрешения из спецификации.
3. Реализовать приглашения с TTL 7 дней, отзывом и одноразовым принятием. Публиковать доменные события `BandCreated`, `MemberInvited`, `MembershipChanged`.
4. Подключить React-экраны бэндов и приглашений к новым HTTP-контрактам; старый сгенерированный клиент из `Services` не расширять.

**Готово, когда:** пользователь из Keycloak создаёт бэнд, приглашает участника и права проверяются на сервере.

## 3. Модуль песен — первый прикладной вертикальный срез

1. Создать `WBand.Modules.SongModule`: песни, авторы, тональность, BPM, размеры, секции по тактам и текст с аккордами C–B.
2. Добавить optimistic concurrency, `contentVersion`, версии и корзину с хранением 30 дней.
3. Реализовать авторизацию через разрешения бэнда, HTTP-команды/запросы Wolverine и UI списка, просмотра и редактора песен.

**Готово, когда:** Editor создаёт, редактирует, восстанавливает и версионирует песню своего бэнда.

## 4. Плейлисты и события

1. Создать `WBand.Modules.PlaylistModule`: события, порядок песен, паузы/автостарт/кроссфейд и индивидуальные key/BPM/structure overrides.
2. Валидировать принадлежность песни бэнду и публиковать события изменения `contentVersion`.
3. Подключить страницы плейлистов и форму события.

**Готово, когда:** для выступления можно собрать плейлист без изменения оригиналов песен.

## 5. Файлы, стемы и подготовка воспроизведения

1. Завершить `FileModule`: presigned upload/download, SHA-256, ограничения MIME/размера, права доступа и очистка незавершённых загрузок.
2. Создать `WBand.Modules.StemModule`: WAV-стемы, группы, метаданные и связь с песнями.
3. События изменения песен, плейлистов и стемов направлять в Wolverine outbox для инвалидации будущего кэша.

**Готово, когда:** Editor безопасно загружает и группирует стемы, а доступ к ним ограничен бэндом.

## 6. Рендер, плеер и Live

1. Определить контракты `RenderPlan` и `RenderJob`; создать отдельный worker-агент для FFmpeg, MinIO и идемпотентной очереди рендера.
2. Доработать desktop AgentPlayer: загрузка кэша, транспорт, solo/mute, уровни, панорама и MIDI.
3. Добавить Live-сессии: сначала LAN master–slave, затем WebSocket для зрителей.

## 7. Завершение MVP

Добавить импорт TXT/DOCX/PDF, экспорт PDF, каталог/публикацию, уведомления, наблюдаемость (OpenTelemetry, Prometheus, Grafana, Loki) и безопасность выпуска. После миграции всех сценариев удалить `Services/`, `src/` и их устаревшие контракты отдельной проверяемой задачей.
