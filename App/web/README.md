# WBand — Next.js

Рабочий интерфейс перенесён из `App/web-vite` на Next.js App Router. Доступны главная,
группы, участники и роли, приглашения, песни, секции с текстом и аккордами,
просмотр и восстановление истории метаданных. Заготовки плейлистов, сцены, чата,
стемов и старого плеера не подключены: действующий WebAPI их не обслуживает.

## Запуск

Состав системы запускается через `App/WBand.AppHost/WBand.AppHost.csproj`:

```sh
aspire start --apphost App/WBand.AppHost/WBand.AppHost.csproj
```

Открывайте приложение через ресурс `proxy` (по умолчанию `http://localhost:4000`).
BFF обрабатывает OIDC, HttpOnly-cookie, выход и CSRF-защиту; OAuth-токены остаются
на сервере. Каждый защищённый маршрут Next.js проверяет сессию на сервере.
Клиентский провайдер получает профиль и CSRF-токен через `/auth/me` и синхронизирует
локальный профиль через `/api/user/me` до запуска запросов рабочих экранов.

Для отдельного запуска фронтенда при работающем BFF:

```sh
bun install
BFF_ORIGIN=http://localhost:4000 bun run dev
```

`BFF_ORIGIN` — серверный адрес доверенного BFF, без `NEXT_PUBLIC_`.
В Aspire он передаётся автоматически. API и авторизация в браузере используют
относительные URL; Next.js rewrites поддерживают отдельный dev-сервер.
В production публичная точка входа также должна проходить через BFF,
чтобы callback, session cookie и CSRF cookie принадлежали одному origin.

## Структура

- `app/` — серверные страницы, маршруты, layouts, loading и error boundaries.
- `views/`, `widgets/`, `features/` — интерактивные клиентские экраны и редакторы.
- `lib/server/session.ts` — проверка BFF-сессии с `no-store` и мемоизацией в пределах запроса.
- `lib/axios-instance.ts` — общий HTTP-клиент с CSRF и обработкой истечения сессии.
- `lib/form-schemas.ts` — Zod-валидация форм; серверная валидация остаётся в WebAPI.
- `lib/generated/` — только результат Orval, редактирование и копирование вручную не нужны.

Формы используют React Hook Form, Zod и shadcn Field. REST-запросы и обновление
кеша выполняются через TanStack Query; авторизацию каждой операции и проверку
версии выполняет WebAPI. Редактор сохраняет исходный `contentVersion`, чтобы
фоновая перезагрузка не скрыла конфликт параллельного редактирования.

UI использует существующий `base-nova` на Base UI. Стили и ранее установленные
компоненты сохранены. Новые компоненты устанавливайте через CLI:

```sh
bunx shadcn@latest add <component>
```

## API и проверки

```sh
bun run generate-api-clients
bun run typecheck
bun run lint
bun run test
bun run build
```

Orval генерирует клиент WebAPI и клиент BFF из их OpenAPI. Генератор Aspire
включается явно настройкой `GenerateApiClients=true` после изменения HTTP-контрактов;
обычный запуск сохраняет существующие клиенты. Для экспортированных схем:

```sh
WEBAPI_OPENAPI=/path/to/webapi.json AUTH_OPENAPI=/path/to/auth.json bun run generate-api-clients
```

`bun run generate-api` оставлен как алиас. Клиенты не требуют копирования из Vite.
Пользовательские QueryClient и i18next создаются в провайдере; язык хранится
в cookie и учитывается при серверном рендеринге. Переключение темы и настроенные
шрифты сохранены.

## Проверка переноса

Проверены production-сборка, TypeScript, ESLint, 21 тест фронтенда,
37 интеграционных тестов API групп/песен/профиля и 17 тестов BFF.
Через браузер проверены вход и выход, создание и переименование группы,
приглашение с ролью Admin, создание и редактирование песни, восстановление
версии, секции с сохранением пробелов и переносов, язык после перезагрузки,
мобильное меню и удаление группы с песней и приглашением.

Полный проект `Tests/WBand.Authentication.Tests` содержит прежние API-тесты
с зависимостями от удалённых `Auth` и `Shared`; он пока не собирается целиком.
Актуальные `ProxyAuthenticationTests` и `ProxyRoutingTests` проверены отдельным
временным тестовым проектом, без исключения старых тестов в репозитории.
В полном наборе WebAPI также обнаружено падение
`KeycloakEventHandlerTests.Handle_WhenPublicationFails_UserRemainsCommitted`;
этот сценарий обработки событий не изменялся при переносе.

## События и сцена

В разделе «События» владелец или администратор группы создаёт мероприятие, указывает дату/время и место, добавляет песни своей группы и меняет их порядок. Участники просматривают событие и открывают «На сцену»: все песни с секциями отображаются сразу, доступны переходы по номерам и размер текста A−/A+. События сохраняются серверным модулем `Modules/WBand.Modules.EventModule`; миграция применяется при старте WebAPI.

В секциях песни используйте, например, `Интро` и аккорды `[| Am | Dm | C | G |]`. Аккорды в квадратных скобках подсвечиваются в превью и на сцене; также поддерживаются встроенные `[Am]` в тексте.

## Редактор партий и сценический режим

В редакторе выбранной партии показаны все общие секции песни. Каждую секцию
можно сохранить отдельно, а «Сохранить всё» отправляет изменённые секции одной
атомарной операцией. Переключение партии сохраняет черновики на открытой странице;
обновление данных не продвигает ревизии несохранённых секций.

На сцене для каждой песни выбирается одна партия. Показываются только её секции.
Выбор хранится в `localStorage` отдельно для пользователя и песни; название
последней выбранной партии служит подсказкой для других песен. Если сохранённая
партия удалена, нужно выбрать новую — чужое содержимое автоматически не показывается.
При недоступном хранилище выбор работает в текущем сеансе страницы.
