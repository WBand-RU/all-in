# Состояние WBand и порядок завершения

Актуализация: 22.10.2026. Источник истины — текущий код, состав `WBand.slnx`
и результаты проверок. Старые отметки «готово» в документации не подтверждают
готовность текущего приложения.

Архитектурное решение: **EF Core + PostgreSQL; Marten не используем**.
Новые модули и перенос прежних модулей используют собственные `DbContext`,
схемы PostgreSQL и миграции EF Core. Упоминания Marten описывают только
историческую реализацию, а не направление дальнейшей разработки.

## Карта приложения

| Область | Реализация | Состояние подключения |
| --- | --- | --- |
| Локальный запуск | `App/WBand.AppHost` | Aspire: PostgreSQL, RabbitMQ, Redis, RustFS, Keycloak, API, BFF, Next.js |
| Вход и сессии | `App/WBand.WebProxy` | BFF, OIDC, серверная сессия, CSRF, маршрутизация API |
| Пользователи, группы, песни | `App/WBand.WebAPI` | EF Core/PostgreSQL, Wolverine HTTP и сообщения |
| Содержимое песни | `App/WBand.WebAPI/Endpoints/Songs` | Общие секции, партии, ячейки текста с ревизиями, атомарное сохранение партии |
| События | `Modules/WBand.Modules.EventModule` | Отдельный контекст EF Core и схема `events`, Wolverine-контракты интеграции |
| Интерфейс | `App/web` | Next.js App Router, группы, приглашения, песни, события и сцена |
| Файлы, стемы, рендер | `Modules/FileModule`, `StemModule`, `MixerModule`, `App/WBand.MixerWorker` | Код существует, но эти проекты и worker не подключены к текущему решению/запуску |
| Прежние реализации | `Services`, `src`, `App/web-vite` | Не развивать; наличие экранов здесь не означает доступность в Next.js |

Основной пользовательский сценарий для приёмки: вход через BFF → создание
группы → создание песни → заполнение секций и партий → событие со списком
песен → выбор партии в режиме сцены. Проверять владельца и Viewer, запрет
доступа к чужой группе, обновление страницы и конфликты ревизий.

## Проверенная исходная точка

- Debug-сборка решения: без ошибок и предупреждений.
- Два исходных прогона `dotnet test WBand.slnx --configuration Release --no-restore`:
  все 77 тестов прошли. Финальные повторы выявили нестабильность, см. ниже.
- Release-сборка всего решения: без ошибок и предупреждений.
- После восстановления клиента из OpenAPI: все 40 тестов фронтенда, ESLint
  и `bun run typecheck` прошли. Семь регрессионных тестов выбора проектов CI прошли.
- Один повторный полный прогон дал 76/77: HTTP 500 при создании партии в
  `SavePartition_WhenSeveralSectionsChange_SavesThemTogetherAndLeavesOtherPartitionsAlone`.
  Изолированный диагностический запуск этого теста прошёл; причина разового
  сбоя не установлена. Для проверки повторного появления сохранён подробный
  журнал полного прогона: `/tmp/wband-final-tests.log`.
- Последний подробный прогон: **75/77**, падали
  `Event_WhenMemberOrOutsiderRequests_EnforcesPermissionsAndFiltersLists` и
  `MigrateMatrix_WhenUpgradingLegacyOrFlatContent_PreservesTextAndSharedSections(true)`.
  Журнал фиксирует `NpgsqlException` / `EndOfStreamException` — разрыв
  PostgreSQL-потока. Сценарии отказа меняются; источник разрывов не установлен.
  Стабильное прохождение серверного набора пока не подтверждено; повторы
  операций и отключение проверок в код не добавлялись.
- Production-сборка `bun run build --webpack` прошла со всеми маршрутами.
  Обычный `bun run build` с Turbopack блокируется запретом среды на служебный
  порт; первоначально также была недоступна загрузка Google Fonts.
- В Chrome пройден сценарий владельца на отдельной локальной тестовой учётной
  записи: регистрация → вход → группа → песня → секция → партия → текст с
  аккордом → событие с песней → сцена. Сохранённый текст проверен после
  перезагрузки, на сцене подтверждены выбранная партия и подсветка аккорда.
  Снимок результата: `/tmp/wband-stage.png`. Приёмка Viewer и запрета доступа
  к чужой группе в браузере остаётся отдельной задачей.

## Исправления основы

- CI запускает актуальное решение вместо прежнего `WBand.Architecture.Tests`.
- Изменения WebAPI.Tests, BFF, AppHost и ServiceDefaults запускают серверную
  проверку. Для выбора проектов добавлены регрессионные тесты.
- Release больше не пытается собирать Next.js как ASP.NET Website; веб
  проверяется своим заданием Bun.
- Обычный запуск Aspire не перезаписывает API-клиенты. Генерация включается
  явно через конфигурацию `GenerateApiClients=true`, только после изменения
  HTTP-контрактов. Для CLI можно задать переменную окружения перед запуском:
  `GenerateApiClients=true aspire start --non-interactive --apphost App/WBand.AppHost/WBand.AppHost.csproj`.

## Оставшаяся работа

1. Завершить приёмку ролей и устранить нестабильность запуска.
   При текущей проверке RustFS вернул 503 `waiting for iam` при создании бакета,
   а API завершился после разрыва PostgreSQL-соединения при миграции событий.
   При следующем старте зафиксирован разрыв RabbitMQ-соединения. После повторного
   запуска API стал доступен и браузерный сценарий прошёл; причина разрывов
   пока не установлена, повторный запуск не считается исправлением.
2. Восстановить полноценную проверку BFF: прежний Authentication.Tests содержит
   зависимости от удалённых проектов; существующие тесты proxy нужно подключить
   к актуальному тестовому проекту.
3. Исправить упаковку: Dockerfile API ссылается на прежние пути модулей;
   `App/web/Dockerfile`, который использует CI, отсутствует. Проверить worker
   отдельно, прежде чем включать его публикацию и запуск.
4. Завершить выделение владельцев данных в модули. Добавить надёжную исходящую
   очередь: сейчас события публикуются после commit без persistent outbox,
   поэтому возможна потеря уведомления при сбое процесса.
5. Подключать вертикальными срезами: файлы/стемы → рендер → плеер → Live и
   оффлайн. Затем импорт/экспорт, каталог и остальные требования спецификации.
