# Требования WBand MVP

Дата: 22.10.2026. Статус: согласованные продуктовые требования MVP.

Документ собирает решения, подтверждённые при обсуждении MVP. Критерии
приёмки уточняют их проверяемое поведение; нерешённые вопросы перечислены
отдельно. Наличие функции в прежнем коде не подтверждает её готовность.
Широкая спецификация `WBAND_SYSTEM_SPEC_v1.md` остаётся описанием развития
продукта; состав первого выпуска определяется этим документом.
План реализации и предлагаемые технические параметры приёмки:
[tasks/plan.md](../tasks/plan.md); задачи: [tasks/todo.md](../tasks/todo.md).

## 1. Цель и пользователи

Группа поклонения готовит репертуар и программу служения. Каждый музыкант
открывает нужную партию песни на своём устройстве, самостоятельно перемещается
по программе и может использовать заранее загруженное событие без интернета.

MVP — веб-приложение с адаптацией к экранам телефонов, планшетов и компьютеров.
Установка на устройство не требуется. Отдельное нативное приложение не входит
в первый выпуск.

## 2. Предметные области и зависимости

| Область | Ответственность | Зависит от |
| --- | --- | --- |
| `groups` | Прикладные профили, группы, членство, роли, приглашения | Аутентификация Keycloak |
| `repertoire` | Песни, общая структура, партии, содержимое, импорт, транспонирование | Контракты доступа `groups` |
| `events` | Программа служения, тональности и структура песен для события | Контракты доступа `groups`, чтение `repertoire` |

Сцена и оффлайн-просмотр используют данные этих областей и не требуют
отдельных серверных БД. Импорт входит в репертуар. Зависимости однонаправленные:
`groups` → `repertoire` → `events`, при этом `events` также использует `groups`.
Это границы ответственности, а не требование немедленно переносить текущий код.

## 3. Подтверждённые функциональные требования

### MVP-01. Учётные записи, группы и приглашения

- Свободная регистрация и вход через Keycloak.
- Любой зарегистрированный пользователь может создать группу и становится её владельцем.
- Несколько независимых групп; пользователь может состоять в нескольких группах.
- Репертуар, события и членство изолированы между группами.
- Вступление в существующую группу — по одноразовому приглашению со сроком 7 дней.
- Роль назначается внутри группы, а не глобально для пользователя.
- В группе ровно один владелец. Передать владение другому действующему
  участнику может только текущий владелец; прежний владелец при передаче
  становится администратором.
- Владелец не может выйти из группы до передачи владения. Администратор
  не может удалить владельца из группы или изменить его роль.
- Передача владения сохраняет правило одного владельца, в том числе
  при одновременных запросах, без промежуточного состояния без владельца.

| Роль | Подтверждённые возможности |
| --- | --- |
| Владелец | Все действия, включая удаление группы и передачу владения |
| Администратор | Управление участниками, песнями, импортом, событиями и корзиной |
| Редактор | Редактирование песен, импорт и работа с событиями; применение доступных версий из истории, без удаления песен/событий/версий и управления корзиной |
| Участник | Просмотр, сцена, оффлайн-загрузка и личные настройки отображения |

Критерии приёмки: пользователь может работать с двумя своими группами;
пользователь без членства не получает их защищённые данные через API;
участник не может выполнять редакторские операции; использованное или
просроченное приглашение не предоставляет новое членство.
После передачи владения новый участник становится единственным владельцем,
а прежний — администратором. Попытки владельца выйти без передачи владения
и администратора удалить или понизить владельца отклоняются сервером.

### MVP-02. Песня, структура и партии

- Метаданные песни: название, автор/исполнитель, исходная тональность,
  BPM, музыкальный размер и теги.
- Обязательно только название. Остальные метаданные можно заполнить позже.
- Транспонирование требует указанной исходной тональности; приложение
  не должно угадывать её при отсутствии значения.
- Поиск по репертуару работает внутри выбранной группы, без учёта регистра,
  по названию, автору/исполнителю и тексту партий. Доступна фильтрация по тегам.
- При выборе нескольких тегов показываются только песни, содержащие
  все выбранные теги одновременно. Дополнительный тег сужает выборку.
- У песни есть единый упорядоченный список частей структуры: например,
  Интро, Куплет, Припев. Названия частей произвольные.
- Части могут иметь одинаковые названия, но остаются отдельными сущностями
  со своими идентификаторами и содержимым. Название не является ключом части.
- Для части поддерживаются примечание, сокращение и цвет маркера.
- У песни есть партии: например, «Слова», «Аккорды», произвольные партии музыкантов.
- Содержимое образует матрицу «часть структуры × партия».
- Каждая ячейка хранит отдельный обычный текст; пустое содержимое допустимо.
- Список частей общий для всех партий песни. Отсутствие слов в Интро не
  удаляет Интро из структуры и не затрагивает аккорды этой части.
- Ручное создание и редактирование содержимого обязательно для MVP.

Критерий приёмки: в песне с Интро, Куплетом и Припевом созданы партии
«Слова» и «Аккорды»; в Интро слова пустые, аккорды заполнены. Сохранение
слов Куплета не меняет его аккорды или содержимое других частей.
Дополнительные критерии: песня создаётся с одним названием; отсутствие
необязательных метаданных не блокирует редактирование и просмотр.
До указания исходной тональности транспонирование недоступно.
Поиск по строке из текста партии находит песню независимо от регистра;
песни других групп не попадают в результаты.
При выборе тегов «Рождество» и «Спокойная» находятся только песни с обоими
тегами; песня с одним из этих тегов в результат не попадает.

### MVP-03. Текстовый редактор и отображение аккордов

- Редактор работает с обычным текстом, без обязательной визуальной разметки.
- Аккорды записываются в квадратных скобках, в том числе внутри строк текста.
- В сценическом отображении партии аккорды внутри скобок подсвечиваются,
  а сами квадратные скобки не отображаются.
- Исходные пробелы и переносы строк сохраняются.
- Редактирование и транспонированное отображение не удаляют скобки из исходника.

Критерии приёмки: исходник `[Am] Строка` отображается с выделенным `Am`
без скобок; повторное открытие редактора возвращает исходную запись.
Пустые строки и отступы сохраняются после сохранения и перезагрузки.

### MVP-04. Импорт JSON

- Импорт одного JSON-файла или папки файлов в выбранную группу.
- Поддерживается формат примеров каталога `songs` в корне репозитория.
- Если присутствует `content.textStructure.parts`, его элементы задают общую
  структуру песни в исходном порядке: `name` — название части, `content` —
  начальный текст соответствующей части партии «Слова», `comment` — примечание,
  `abbreviation` — сокращение, `color` — цвет маркера.
- Каждое появление части из `textStructure.parts` сохраняется отдельно
  со своим идентификатором. Повторные «Припевы» не объединяются автоматически,
  поскольку их содержимое может различаться.
- Если `content.text` отличается от содержимого `textStructure`, предпросмотр
  показывает расхождение и сохраняет оба источника до решения пользователя.
  Отличающийся текст не отбрасывается и не перезаписывает слова молча.
- При отсутствии `textStructure` источником партии «Слова» служит `content.text`.
- Независимо от наличия `textStructure`, `content.chords` задаёт партию
  «Аккорды», каждый элемент `content.customMetas` —
  отдельную партию с исходным названием и текстом.
- Аккорды и дополнительные партии распределяются по общей структуре там,
  где соответствие однозначно; неоднозначности разрешаются в предпросмотре
  с сохранением исходного текста.
- `_manifest.json` является служебным файлом, а не отдельной песней.
- Перед сохранением показывается предварительный просмотр результата:
  данные песни, партии, структура и распределение содержимого.
- Однозначно определяемые данные сопоставляются автоматически; пользователь
  может поправить результат до сохранения.
- Неоднозначный исходный текст сохраняется целиком и предоставляется для
  ручной разметки; импорт не должен молча терять содержимое.
- Повторная песня определяется по исходному `id` внутри выбранной группы.
- При совпадениях пользователь получает предупреждение; по умолчанию
  повторные песни пропускаются. Обновление существующей песни требует явного выбора.
- При явно выбранном обновлении существующая песня целиком заменяется
  результатом предварительного просмотра. Прежнее состояние сохраняется
  в истории версий; результат замены становится новой текущей версией.
- Если замена удаляет часть структуры, используемую в событии, включая
  событие в корзине, обновление отклоняется целиком по правилам MVP-05.
  Не допускается частичное применение замены или молчаливое изменение событий.
- Результат импорта показывает добавленные, пропущенные песни и ошибки.
- В MVP импортируются метаданные и текстовое содержимое песен. Вложения
  исходного JSON (аудио, документы и другие файлы) не переносятся; файлы
  по внешним ссылкам автоматически не скачиваются.
- Неперенесённые вложения явно перечисляются в предварительном просмотре
  и итоговом отчёте импорта. Их наличие само по себе не делает текстовую
  часть песни ошибочной и не блокирует её импорт.
- Ошибки отдельных JSON-файлов не блокируют импорт остальных корректных
  песен. Пользователь видит ошибки по каждому файлу и может запустить импорт
  корректных записей.
- Каждая песня сохраняется атомарно: её данные, структура, партии и тексты
  сохраняются целиком либо не сохраняются вовсе. Частично созданные песни
  недопустимы; весь пакет не обязан сохраняться одной общей транзакцией.

Примеры содержат `content.text`, `content.chords`, `content.customMetas`
и, не во всех файлах, `content.textStructure.parts`. Отсутствующее поле
не означает автоматически повреждённый файл. Точное сопоставление формата
нужно описать отдельным контрактом импорта до реализации.

Критерии приёмки: импортируются одиночный файл и папка примеров;
служебный manifest не создаёт песню; повторный импорт предупреждает
о совпадениях и без явного выбора не меняет ручные правки.
В папке с корректным и ошибочным JSON-файлами пользователь видит ошибку
конкретного файла и может импортировать корректную песню. При ошибке
сохранения песни в системе не остаётся частично созданной структуры или партий.
Подтверждённое обновление повторной песни применяет весь результат предпросмотра,
а прежнее состояние доступно в истории. Если замена удаляет используемый
Припев, песня и события остаются без изменений, а импорт сообщает об ошибке
этой записи; остальные корректные записи могут быть импортированы.
Файл с вложениями позволяет импортировать метаданные и текст песни;
предпросмотр и отчёт показывают неперенесённые вложения, а внешние файлы
не скачиваются автоматически.
Импорт структуры с двумя частями «Припев» сохраняет обе части в исходном
порядке и с их собственным содержимым. Примечания, сокращения и цвета
сохраняются. При расхождении `text` и `textStructure` оба источника видны
до подтверждения результата; один источник не заменяет другой молча.

### MVP-05. События и программа служения

- Событие принадлежит группе и содержит дату, место и упорядоченную программу
  из позиций с песнями и текстовых пунктов без песни.
- Текстовый пункт содержит название и примечание: например, «Молитва»,
  «Объявления» или «Перерыв». Он занимает своё место в программе и отображается
  на сцене, в том числе при оффлайн-просмотре.
- Использованные названия текстовых пунктов запоминаются и предлагаются
  при последующем вводе. Пользователь может выбрать подсказку или ввести
  новое название; свободный ввод не ограничен списком подсказок.
- Подсказки названий общие внутри группы: название, использованное одним
  редактором, предлагается другим редакторам этой группы. Названия из других
  групп в подсказки не попадают.
- Одну песню можно добавить в событие несколько раз. Каждое появление —
  самостоятельная позиция программы со своей тональностью и порядком частей,
  ссылающаяся на ту же исходную песню.
- Изменение, перемещение или удаление одной позиции не меняет настройки
  других появлений этой песни и не удаляет исходную песню.
- В событие можно добавить только неудалённую песню той же группы.
- Нельзя удалить песню, пока она используется хотя бы в одном событии.
  Удаление отклоняется целиком; песня не помещается в корзину и не удаляется
  автоматически из программы события.
- Это ограничение действует и для событий в корзине: они сохраняют ссылки
  на песни и блокируют их удаление до окончательного удаления события.
- Нельзя создать или изменить событие так, чтобы добавить удалённую песню.
  Ограничения проверяются сервером и сохраняются при одновременном добавлении
  песни в событие и её удалении: итоговое состояние с такой ссылкой недопустимо.
- Для песни в событии задаётся тональность, общая для участников.
- Тональность события не изменяет оригинальную тональность песни.
- В событии можно задать свой порядок частей песни и повторять части.
- Индивидуальная структура события не изменяет оригинальную структуру песни.
- Тексты партий берутся из соответствующих частей песни.
- При открытии события онлайн используются актуальные тексты и аккорды
  исходных песен, включая сохранённые после создания события исправления.
- Уже открытая сцена не меняется автоматически при правках исходной песни;
  пользователь получает актуальное содержимое при ручном обновлении.
  Оффлайн-копия обновляется отдельно по правилам MVP-07.
- При наличии связи открытая сцена сообщает об изменениях ненавязчивой
  пометкой «Есть изменения» и предлагает кнопку «Обновить». Содержимое
  заменяется только по нажатию пользователя.
- После ручного обновления сохраняются выбранная позиция программы
  и партия, если они ещё доступны. Если позиция или партия удалена,
  приложение сообщает об этом и предлагает выбрать другую; молчаливое
  переключение на произвольную позицию или партию не допускается.
- Нельзя удалить часть исходной структуры песни, пока она используется
  в структуре хотя бы одного события, включая события в корзине. Сначала
  нужно убрать соответствующие ссылки из событий либо окончательно удалить
  эти события.
- Этот запрет действует и для косвенного удаления частей при восстановлении
  старой версии песни или обновлении через повторный импорт. Конфликтующее
  изменение отклоняется без частичного изменения песни или программ событий.
- Проверка ссылок на части структуры выполняется сервером и сохраняет
  целостность при одновременном изменении песни и события.

Критерии приёмки: песня в C открывается в D в выбранном событии, а оригинал
остаётся в C. Последовательность «Куплет → Припев → Припев» отображается
на сцене именно в таком порядке, без изменения оригинальной структуры.
Попытка удалить используемую песню отклоняется без изменения песни и события.
Добавление удалённой песни отклоняется без изменения программы. При одновременных
запросах на удаление и добавление допустима только одна из конфликтующих операций.
Удаление Припева, используемого в событии, отклоняется. Восстановление версии
или повторный импорт, исключающие этот Припев, также отклоняются без изменения
песни. После устранения всех ссылок удаление части становится допустимым.
Исправление слов песни видно при следующем открытии события онлайн.
Открытая до исправления сцена и ранее загруженная оффлайн-копия сохраняют
прежнее содержимое до соответствующего ручного обновления.
При доступном обновлении сцена показывает пометку и кнопку без замены
текста. Нажатие обновляет содержимое с сохранением доступного выбора;
утрата выбранной позиции или партии сопровождается понятным сообщением
и возможностью выбрать другую.
Одна песня может стоять в начале программы в C и в конце в D с другим
порядком частей. Обе позиции отображаются на сцене и в оффлайн-копии
в своём порядке и со своими настройками; правка одной не меняет другую.
Программа «Песня → Молитва → Песня» сохраняется в указанном порядке
и целиком доступна на сцене и оффлайн. Ранее использованное название
«Молитва» предлагается при создании следующего текстового пункта;
пользователь может вместо него ввести произвольное новое название.
Название текстового пункта, сохранённое одним редактором, предлагается
другому редактору той же группы, но не участникам другой группы.

### MVP-06. Личная сцена, транспонирование и каподастр

- Каждый музыкант самостоятельно переключает песни события.
- Порядок песен события общий; позиция просмотра у каждого своя.
- Пользователь выбирает отображаемую партию для каждой песни.
- Транспонирование доступно при просмотре песни и на сцене, без изменения исходника.
- Тональность песни для события используется как общий исходный вариант просмотра.
- Каподастр — личная настройка отображения гитарных форм; не меняет общую
  тональность события и отображение у других участников.
- Транспонирование, каподастр и выбранная структура события доступны оффлайн.

Критерии приёмки: два участника могут просматривать разные песни и партии;
при тональности события D и каподастре на втором ладу гитарист видит формы C,
а другой участник продолжает видеть D. Оригинальный текст аккордов не меняется.

### MVP-07. Оффлайн-просмотр

- Пользователь заранее загружает событие для просмотра без интернета.
- Копия включает порядок всех пунктов программы, названия и примечания
  текстовых пунктов, содержимое структуры и партий, тональности
  и индивидуальную структуру песен события.
- Интерфейс показывает готовность события к оффлайн-просмотру.
- Редактирование требует подключения к серверу.
- При наличии связи приложение сообщает о доступных обновлениях.
- Обновление копии запускается пользователем вручную.
- Новая копия заменяет старую только после полной успешной загрузки.
- Во время просмотра на сцене содержимое автоматически не меняется.
- На ранее авторизованном устройстве загруженное событие доступно без сети,
  даже если срок серверной сессии истёк. Это разрешает только локальный просмотр
  и не продлевает доступ к серверным операциям.
- При явном выходе из аккаунта его оффлайн-копии удаляются из браузера
  и не предоставляются следующему пользователю устройства.
- При смене аккаунта, в том числе без предварительного явного выхода,
  оффлайн-копии прежнего пользователя также удаляются. Выход или смена
  аккаунта прекращают доступ к его данным во всех вкладках этого браузера;
  открытая в другой вкладке сцена не продолжает показывать прежние данные.

Критерии приёмки: после полной загрузки событие открывается и позволяет
переключать песни и партии без сети. Прерванное обновление не уничтожает
предыдущую рабочую копию. Серверная правка не меняет неожиданно текущую сцену.
Дополнительные критерии: после истечения сессии и при отключённой сети
ранее загруженное событие открывается; после явного выхода его копия
больше не доступна, в том числе после перезагрузки страницы.
При выходе или смене аккаунта в одной вкладке другие вкладки прекращают
показывать данные прежнего пользователя; его оффлайн-копии недоступны
новому аккаунту и после перезагрузки браузера.

### MVP-08. История версий песни

- При явном сохранении изменений создаётся новая версия песни. Изменение
  слов или любого другого текста партии также создаёт новую версию.
- Версия содержит полный снимок песни: метаданные, структуру, партии
  и текст всех ячеек. Можно восстановить содержимое, а не только сведения о песне.
- Перед восстановлением пользователь выбирает версию и видит предварительный
  просмотр её метаданных, структуры и содержимого партий. Просмотр сам по себе
  не изменяет текущую песню.
- Восстановление выбранного снимка создаёт новую текущую версию;
  остальные сохранённые версии остаются в истории.
- Пользователь может удалить историческую версию. Это не меняет текущую
  песню; снимок скрывается из активной истории и помещается в корзину на 30 дней.
- До истечения 30 дней удалённую версию можно вернуть из корзины в историю.
  Это не применяет её содержимое к текущей песне: применение снимка выполняется
  отдельно, с предварительным просмотром.
- Просмотр и восстановление версий доступны владельцу, администратору
  и редактору. Удаление исторических версий доступно только владельцу
  и администратору; запрет для редактора проверяется сервером.
- Неудалённые версии хранятся бессрочно. Автоматическое сокращение истории
  по возрасту или количеству версий не выполняется; удаление возможно только
  по явному действию владельца или администратора.
- Возврат версии из корзины и её окончательное удаление доступны только
  владельцу и администратору. Применение доступного снимка из истории
  остаётся разрешённым редактору и не является возвратом из корзины.

Критерии приёмки: изменение слов Куплета создаёт версию с новым текстом;
предыдущий текст доступен в предварительном просмотре. Закрытие просмотра
не меняет песню. Восстановление возвращает весь выбранный снимок и добавляет
новую версию. Удаление исторического снимка не меняет текущие слова песни.
Редактор может восстановить версию, но попытка удалить её через API
отклоняется; владелец и администратор могут удалить исторический снимок.
Удалённый снимок можно вернуть в историю в течение 30 дней; его возврат
сам по себе не меняет текущую песню.
Неудалённые версии остаются доступны независимо от их возраста и количества
более новых версий.

### MVP-09. Корзина и восстановление удалённых данных

Запрет удаления используемой песни из MVP-05 действует и при отправке в корзину.
Событие в корзине сохраняет программу и блокирует удаление используемых песен.
Окончательное удаление события снимает только его блокировку: если песня
используется другим событием, удалить её по-прежнему нельзя.

Дополнительный критерий приёмки: после отправки события в корзину удаление
его песни отклоняется; событие восстанавливается с сохранённой программой.

- Песни и события при удалении помещаются в корзину на 30 дней.
- Удалённые записи скрываются из рабочих списков.
- До истечения срока запись можно восстановить.
- Отправка песен, событий и исторических версий в корзину, возврат из
  корзины и окончательное удаление доступны только владельцу и администратору.
  Эти ограничения проверяются сервером; редактору и участнику операции запрещены.
- Операции с корзиной не обходят запреты удаления используемых песен
  и частей структуры из MVP-05.

Критерии приёмки: удалённая песня или событие исчезает из рабочего списка,
остаётся доступной для восстановления в корзине в течение 30 дней и после
восстановления возвращается с сохранённым содержимым.
Владелец и администратор могут управлять корзиной; попытки редактора
или участника удалить запись, вернуть её из корзины или удалить окончательно
отклоняются сервером без изменения данных.

## 4. Подтверждённые границы MVP

Не входят: плейбеки, загрузка стемов, микшер, аудиоплеер, рендер,
синхронное переключение сцены ведущим, чат, публичный каталог,
DOCX/PDF-импорт и отдельное desktop-приложение.
Также не входит перенос файловых вложений из импортируемых JSON и их
автоматическое скачивание по внешним ссылкам.

Импорт TXT/Markdown не был подтверждён; обязательный формат импорта — JSON.
Экспорт PDF также пока не согласован и не является обязательством MVP.

## 5. Архитектура и требования к качеству

- ASP.NET Core, модульный монолит; активный интерфейс — Next.js/React/TypeScript.
- Одна БД PostgreSQL, отдельные схемы, `DbContext` и миграции EF Core модулей.
- Marten не используем. Модуль не обращается напрямую к внутренним данным другого.
- Межмодульные контракты и HTTP-обработчики — WolverineFX.
- Основные пользовательские операции выполняются синхронно.
- Outbox нужен для обязательных асинхронных действий: бизнес-изменение
  и намерение отправить сообщение сохраняются атомарно. Получатели устойчивы
  к повторной доставке; inbox применяется по потребности конкретного обработчика.
- Outbox/inbox не добавляются каждому модулю без необходимого сценария.
- Права проверяются сервером; сокрытие кнопки не является проверкой доступа.
- Интерфейс должен быть понятным, доступным с клавиатуры и адаптивным.
- Целевая нагрузка MVP — 100 одновременно работающих пользователей
  суммарно по всем группам. Это ориентир нагрузочной приёмки, а не лимит
  зарегистрированных аккаунтов.
- Тестовый объём репертуара — 1 000 песен на группу. На этом объёме
  проверяются поиск, списки, редактирование и выбор песен для событий;
  это не жёсткий лимит библиотеки.
- Тестовый объём одного события — до 100 позиций программы, включая песни
  и текстовые пункты суммарно. На этом объёме проверяются редактирование,
  сцена и оффлайн-просмотр; это не жёсткий лимит размера события.
- Целевое время отклика обычных действий — до 2 секунд при согласованной
  нагрузке: поиск, открытие песни или события и сохранение правок.
- Пакетный импорт и загрузка события для оффлайн-просмотра могут занимать
  дольше 2 секунд; для них отображается отдельный индикатор прогресса.
- MVP поддерживает актуальные Chrome, Edge, Firefox и Safari, включая
  мобильные браузеры. Основные пользовательские сценарии проверяются
  на телефоне, планшете и компьютере.
- Оффлайн-просмотр доступен в том же браузере, где событие было загружено;
  автоматический перенос локальной копии между браузерами не требуется.
- Интерфейс доступен на русском и английском языках. По умолчанию используется
  русский; пользователь может переключить язык интерфейса.
- Пользовательское содержимое не переводится автоматически: названия
  песен, частей, партий и текстовых пунктов, тексты и примечания сохраняются
  в исходном виде независимо от языка интерфейса.

Это проектные требования, а не утверждение, что текущий код им уже соответствует.

## 6. Проверка и инженерные соглашения

- Серверные проверки: `dotnet build WBand.slnx` и `dotnet test WBand.slnx`.
- Фронтенд из `App/web`: `bun run lint`, `bun run typecheck`, `bun run test`, `bun run build`.
- Локальный состав: `aspire start --non-interactive --apphost App/WBand.AppHost/WBand.AppHost.csproj`.
- Доменные правила покрываются unit-тестами; API, права, миграции и атомарность —
  интеграционными; редактор, импорт, сцена и оффлайн — браузерными сценариями.
- Применяются `.editorconfig` и `AGENTS.md`; публичные C#-контракты имеют XML-документацию.
- Новая функциональность не добавляется в `Services`, `src` или `App/web-vite`.
- HTTP-клиенты генерируются из OpenAPI после изменения HTTP-контрактов.

## 7. Технические уточнения перед реализацией

1. Точный контракт дополнительных метаданных исходного JSON и нормализации
   значений. Согласованные правила структуры, партий, вложений и предпросмотра
   остаются обязательными.
2. Профиль нагрузочного испытания для 100 пользователей и 1 000 песен на группу:
   состав действий, объём текстов, окружение и точная методика измерения 2 секунд.
3. Конкретные размеры экранов для проверки адаптивности и условия проверки
   вместимости браузерного оффлайн-хранилища. Тестовое событие содержит
   100 позиций; ошибка загрузки не должна обозначаться как готовая оффлайн-копия.

Функциональные решения выше подтверждены при обсуждении. Предложения по
техническим уточнениям включены в раздел 4 плана реализации для проверки.
Перечисленные уточнения не разрешают молча менять согласованные функции,
права доступа, ограничения целостности и численные цели приёмки.
